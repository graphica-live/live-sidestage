# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

ユーザーは2種類いる。

- **フレーム作成者（主体）** — 主に TikTok Live の配信者。透過PNGのアイコンフレームを用意し、リスナーへ配る。Google または LINE の OAuth でログインが必要。
- **リスナー（着せ替え利用者）** — 配布された着せ替えURLを開き、自分の画像にフレームを重ねて保存する側。**ログイン不要**で、アカウントも持たない（フレームにパスワードが設定されている場合のみ入力を求められる）。

プロダクトの設計上の主体は作成者側で、リスナー側は「URLを開いて画像を作って保存するだけ」の使い捨て動線として意図的に軽くしてある。

## Product Purpose

配信者が自分のアイコンフレーム（透過PNG）をアップロードすると、リスナー向けの「着せ替えURL」が発行される。リスナーはそのURLで自分の好きな画像を選び、円形の切り抜き位置と拡大率を調整して、フレームを重ねた画像をその場で保存できる。**配信者のコミュニティが揃いのプロフィールアイコンを持てるようにすること**が目的。

## Positioning

`graphica-live/live-sidestage` モノレポ内の6プロジェクトのうち、**TikTok Live 配信者向けの4プロジェクト（analytics / desktop / mobile / TikCaption）とコード上の連携をまったく持たない独立プロダクト**。共通のアカウント基盤も、共通のバックエンドも持たない。TikTok Live の文脈を共有しているだけで、技術的には完全に切り離されている。`tiktok-live-connector` によるギフト/コメント受信の土台にも乗っていない。

同種のアイコンフレーム作成サービスに対する差別化点は、フレーム作成者側に配布・運用の道具（着せ替えURL、パスワード保護、閲覧/装着/Good のカウント、公開ランキング）を持たせている点にある。

## Operating Context

Cloudflare Pages 上で完結する。フロントは React 19 + Vite、APIは Pages Functions。ストレージは Cloudflare の3種を併用する。

- D1 `tikring-db`（binding `DB`） — ユーザー、フレーム、共有URL、閲覧/装着イベントログ
- R2 `profile-frames`（binding `FRAMES_BUCKET`） — フレーム画像・開口マスク・共有プレビュー画像の本体
- KV（binding `SESSIONS`） — セッション

作成者の動線は「Google/LINE でログイン → 透過PNGをアップロード → 開口マスクで“プロフィール画像が見える範囲”を塗る → 着せ替えURLを取得して SNS/配信で配る」。リスナーの動線は「URLを開く → 自分の画像を選ぶ → 円形の位置・ズームを合わせる → 保存」。モバイルでは Web Share API 経由の共有メニュー保存へ、非対応なら通常ダウンロードへフォールバックする。

TikTok のアプリ内ブラウザで開かれることを前提に、専用の警告画面（`BrowserWarning`）を持つ。ボット対策に reCAPTCHA v3 を使う。

## Capabilities and Constraints

- **プラン**は `free` / `pro` の2種。`isEffectivePro()` が判定し、管理者メール（`functions/_auth.ts` にハードコード）は常に pro 扱い。
  - free: アップロードしたフレームの有効期限は **90日固定**。期限切れは日次の cleanup API（GitHub Actions `tikring-cleanup.yml`、JST 12:00）で削除される。
  - pro: 有効期限を指定できる（未指定なら**無期限**）。フレームに任意のカスタム名を付けられる。
- **Pro サブスクリプションの新規受付は停止済み**。`functions/api/checkout/index.ts` は `410 CHECKOUT_DISABLED` を返すだけの実装に置き換えられており、UI側の導線も無効化されている。既存契約者のために `cancel` / `sync` / `webhook` は残してある。実装本体は git 履歴から戻せる。
- **課金で現在生きているのは寄付（単発）のみ**。Stripe Checkout の one-time payment を使い、金額はユーザーが自由入力してサーバー側で検証する。制約は **100円以上・100000円以下・100円単位**（`functions/api/checkout/donate.ts`）。サブスク用の price ID（月額/年額）は `wrangler.toml` に残っているが、新規受付停止により現在は使われない。
- **アップロード制限**: フレーム画像 5MB、開口マスク 1MB、共有プレビュー 2MB。1アカウントあたり**1時間に5枚**まで（超過は `RATE_LIMITED`）。
- **フレームのパスワード保護**が設定できる（設定するとリスナーに入力を求める）。
- **カウンタと公開ランキング**: フレームごとに閲覧数（view）・装着数（wear）・Good 数（good）を数える。公開ランキングは月間閲覧数の **TOP10** と、直近の装着数ベースの **PICK10**（pickup）の2種。フレーム単位でランキング除外（`exclude_from_rankings`）を設定できる。
- 一度でも TOP10 に入ったフレーム（`ever_top10`）は、**所有者が削除しても画像と統計を保全する**（admin専用アーカイブ扱い）。
- **表示名は既定で匿名**。`User000000` 形式の連番を自動採番し、ユーザーが任意の表示名を設定した場合のみそれを使う（マイグレーション `0009` で既存の非管理者名を匿名化済み）。
- 認証は Google と LINE の OAuth のみ。パスワード認証は持たない。
- TikTok プロフィールID（`tiktok_profile_id`）をユーザー設定として保持できるが、**TikTok API との連携はない**（`functions/api/tiktok/` は空）。表示・導線用の文字列。
- **自動テストは無い**。`package.json` に `test` スクリプトは存在せず、検証は `npm run lint` / `npm run build` と本番スモークテストに依存する。
- 本番デプロイ後は GitHub Actions（`tikring-prod-verify.yml`）が Cloudflare Pages の production deployment 完了を待ち、`scripts/prod-smoke-test.mjs` を実行する。**失敗すると直前の成功デプロイへ自動ロールバックする**。

## Brand Commitments

製品名は **TikRing**（UI・OGP・タイトルすべてこの表記）。モノレポ上のディレクトリ名 `TikRIng`（大文字 I が2つ）と npm パッケージ名 `profileimagefitservice` は歴史的経緯による内部名であり、**ユーザーに見せる名前は常に `TikRing`**。統合前の GitHub リポジトリ名は `graphica-live/frame`。

TikTok のブランドカラーを踏襲したダークテーマ（`tiktok-cyan` などのトークン）を使うが、TikTok 公式サービスであると誤認させる表現は取らない。

## Evidence on Hand

- Cloudflare Pages 上で**本番稼働している**。本番URLに対する検証（`/api/health`、トップページ応答、`/api/auth/me`、`/api/frames`、Pro アカウントで `viewCount` / `wearCount` が数値で返ること）が push ごとに自動実行され、失敗時は自動ロールバックする。この仕組みが継続的に回っていること自体が、これらの経路が動いている根拠になる。
- D1 のマイグレーションは 0017 まで積み上がっており、匿名化・イベントログ・過去データのバックフィル（`0013_backfill_legacy_april_view_events.sql`）など**運用の履歴が実データに対して行われている**。
- `scripts/gen-april-ranking-watermarked.mjs` があり、過去に実際のランキングを画像として出力した実績がある。

**無いもの**: ユニットテスト・統合テスト・E2Eテストは一切無い。ブラウザでの体系的な実機検証記録も無い。ユーザー数、フレーム数、寄付額などの実績データ、マーケティング素材、ユーザーレビューは手元に無い。**今後の作業でこれらを捏造しない。**

## Product Principles

- リスナー側は**アカウント不要**を崩さない。URLを開いてから保存まで、ログインを挟まない。
- フレーム作成者の運用道具（配布URL、パスワード、カウンタ、ランキング）は作成者側にだけ置き、リスナー側の画面を重くしない。
- Cloudflare（Pages / D1 / R2 / KV）で完結させ、外部の常駐サーバーを持たない。
- モノレポの他プロジェクトとは連携しない独立プロダクトとして維持する。共通アカウント基盤へ寄せない。
- 本番の壊れは自動ロールバックで即座に戻す。自動テストが無いぶん、本番スモークテストを最後の防波堤として扱う。

## Accessibility & Inclusion

UI は日本語のみで、i18n 対応は範囲外。スクリーンリーダー等の視覚アクセシビリティ要件は現時点で確認・検証されていない。画像の切り抜き・位置合わせという中核操作がポインタ操作に依存しており、キーボードのみでの操作性は未検証。
