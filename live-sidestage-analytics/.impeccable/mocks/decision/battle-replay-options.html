バトル再生 画面構成

既存の BattleDetailModal に再生モードを足す既存サーフェスの拡張。世界(トークン・陣営色の生HEX・font-mono の数値・rounded-xl のパネル)は .impeccable/approved/battle-detail-contributors/spec.md をそのまま継承し、決めるのは構成だけ。 ステージ面のみ常時ダークにする(配信映像の代替面であり、ライト背景に置くと元画面と別物になるため)。

採用構成

ステージ + 計器 — 見ながら読める

前提

構成によらず変わらない前提

陣営色
自陣 #fe4d4d / 相手はバトルスコア降順に #4d9fff → #ffa64d → #b98aff。 クライアントの assignFactionColors をそのまま使い、一覧・詳細・再生で完全に一致させる(サーバーは色を返さない)。WINバッジは #f5c451。
枠割
実画面に合わせる。2コラボ = 左右2分割 / 3コラボ = 左に縦長1枠(全高) + 右に上下2枠 / 4コラボ = 2×2。 左の大枠は常に自陣(実画面と同じ)。右側の枠はバトルスコア降順に並べる。 枠の縦横比は実バトル画面の実測に合わせる(2コラボ ≈ 0.55 の縦長、3コラボの右2枠と4コラボの各枠 ≈ 1.09)。 貢献者ボードやコントロールのためにステージを縮めない。
採らないもの
実画面の A1 / A3 チーム記号バッジ、ファンクラブ導線、ミュートアイコン、フォロー(+)ボタンは出さない。 いずれも再生時点では操作対象が存在せず、押せない飾りになるため。順位バッジ・名前チップ・スコアは出す。
チーム戦
2vs2 / 1vs3 のように1陣営に複数人いる場合、色はチーム単位で1色 (自チーム #fe4d4d / 相手チーム #4d9fff)。同じチームの2人目以降は同じ色を薄くした背景で区別する。 上部スコアバーは陣営数ぶんのセグメント(2vs2 も 1vs3 も2本)で、値は BattleTeam.officialScore。枠の中の数字は個人スコアで、合計とは別物。 枠割は列でチームを分け、列の境目だけ太い線で割る。1vs3 は左に自陣1枠(全高) + 右に相手3枠。 WINバッジはチームの先頭枠だけに出す。
貢献欄
リスナー名は出さず、アイコンと金額だけ並べる(場所の節約)。右端が1位で、左へ向かって順位が下がる。 1位のアイコンだけ金 #f5c451 の枠。 金額は font-mono + tabular-nums。名前はホバー/長押しの title に持たせる。 公開シェアではアバターURLを出せないので、ここもニックネーム頭文字の円になる。
ギフトレーン
上下2段。上段は少額ギフト、下段は高額ギフトを消化する。 下段に流す高額ギフトが無い区間は、上下段とも少額の消化に使う(下段を空けたままにしない)。 下段のカードは一回り太く、アイコン・ギフト画像・件数も大きい。各段の同時表示は最大5本、超過時は新しい方を優先。 1vs1 は左右2レーン(自陣=左から / 相手=右から)。3人以上のコラボは自陣のレーンだけ出す (相手が2〜3人いると誰の分か判らず、枠も潰れるため)。 位置は赤帯・コントロールに被らない高さまで持ち上げる。
グローブ
クリティカル(グローブ)が刺さったギフトは、スライドインカードの外側末端にグローブのマークを出す。 multiplierValue が 5 は赤 #fe4d4d、6 は金 #f5c451。マークだけで、倍率の数字は出さない。 P4 で凍結した giftEvents(t,a,s,g,c,d)に倍率が無いので、battle-replay-contract.ts へ 倍率フィールドを1つ足す(既存フィールドは変えない)。P2 デプロイ前のギフトは倍率が未観測 → マークを出さない。
リップル
ギフトのスライドインに同期して、受け取った配信者のアイコンから陣営色の輪が広がる。 輪の最大倍率はそのギフトのスコア加算値で変わる(小口は1.5倍程度、大口は3倍超)。 CSS変数 --ripple / --fc を要素に載せ、keyframes は1本だけ持つ。ライブラリは足さない。 prefers-reduced-motion では拡大せず不透明度だけ落とす。
映像がない
実映像は保存していない。枠は陣営色の放射グラデ + 配信者アイコン + 名前チップで埋める。実写風の合成画像は作らない(無い映像があるように見せない)。
公開シェア時
P4 の対応でリスナーのアバターURLは公開ペイロードに載らない(URLのパスにTikTokハンドルが含まれるため)。 公開再生ではギフトバーのアイコンをニックネーム頭文字の円で描く。配信者アイコンは公開でも出る。
赤帯の条件
measured のときだけ赤帯 + 残り秒数。inferred は帯を出さず隅のチップ「初回ボーナス: ×2(推定)」。 unknown はチップ「初回ボーナス倍率: 記録なし」。 帯は赤1種類で、文言だけ差し替える(紫など別色の帯は作らない)。 ボーナスミッションも同じ赤帯に載せ、カウントダウンは出さない。文言は目標の種別で2通り: 人数系は「ボーナスミッション  3人からギフトを受け取る」、 スコア系は「ボーナスミッション  5,000pt受け取る」。数値は font-mono。 種別は targetType、値は progressTarget から出す。 ミッション達成後のボーナスタイムは「ボーナスタイム  ×3倍」+ 残り秒数 (倍率は rewardMultiple、区間は settledAt 以降。ここだけはカウントダウンを出す)。 tiktok_battle_bonus_missions は本番0件で、収集はP1で実装する。
シークバーの目盛
大口ギフト(totalDiamonds 上位)の位置に陣営色のティックを立てる。どこで動いたかが再生前に見える。
スコアは階段
公式スコアは補間しない。t <= elapsedMs の最後の点をそのまま出す。数値は必ず font-mono + tabular-nums。

画像素材の判定

該当なし。 生成画像を1点も使わない。理由は3つ。

(1) ステージの枠は「記録の無い映像」を表す面であり、それらしい人物・配信風の絵を置くと実際には保存していない映像があるかのような偽装になる。 (2) 配信者・リスナーのアイコンは TikTok 由来の実アバター(署名付きURL)で、生成画像で代替する対象がない。 (3) ギフト画像は TiktokGiftCatalog の実画像を giftId で引く。空状態のアイコンも既存の lucide-react で足りる。

グローブのマークだけ lucide-react に無いので、単色SVGを自作して mask で着色する(銀 #aab1c0 / 金 #f5c451)。 1グリフのUIアイコンであり、生成画像の対象にしない。

公開再生でリスナーアイコンが出せない件は、生成画像ではなくニックネーム頭文字の円で埋める(恒久対応は不透明IDのプロキシで、P5の範囲外)。
