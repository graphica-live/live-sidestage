# Product

<!-- impeccable:product-schema 1 -->

## Platform

windows（Electron デスクトップアプリ / NSIS インストーラ配布）

## Users

主要ユーザーは日本語で配信する TikTok Live 配信者。自分の声に字幕を付けたい配信者と、視聴者コメントを音声で聞きたい配信者の両方を想定している。開発者自身が実運用しつつ、`electron-updater` による自動更新（配信元 `https://update.graphica-produce.com/tikcaption/win`）で外部ユーザーへも配布している。バージョンは 1.0.21 に達しており、リリース後の実利用に起因するバグ修正コミット（録音デバイス重複、AGC 無効化、VAD モデルのオフラインロード、TikTok Live の無音切断検知など）が継続的に入っている。

なお、実際の配布規模・利用者数を示す資料はリポジトリ内に存在しない。

## Product Purpose

配信者のマイク音声をリアルタイムに文字起こしし、字幕オーバーレイとして配信画面に重ねる。あわせて TikTok Live の視聴者コメントを VOICEVOX で読み上げる。目的は、聞き取りづらさ・音声のみでは届かない情報を字幕で補い、配信者がコメント欄を注視しなくても視聴者の発言を把握できるようにすること。

字幕は日本語表示に加えて外国語への翻訳表示にも対応しており、海外視聴者にも配信内容を伝えられる。

## Positioning

**独立プロダクト**。モノレポ内の他5プロジェクト（analytics / desktop / mydesktop / mobile / TikRIng）とコード上の連携を一切持たない。アカウント登録もサーバーサイドのバックエンドも持たず、PC 内で完結する。

差別化点は、クラウド ASR に依存せず **オンデバイスで日本語 ASR（NVIDIA NeMo Parakeet `nvidia/parakeet-tdt_ctc-0.6b-ja` + silero-VAD）を回す**こと、および TikTok Live 配信という用途に特化した語彙補正（配信用語・ギフト名・配信者名の内蔵辞書）を最初から持っていること。字幕と読み上げが1つのアプリに同居し、どちらも OBS ブラウザソース1本で取り込める。

## Operating Context

配信者は OBS 等で配信しながら TikCaption を常駐させる。タスクトレイ常駐型で、メインウィンドウは「字幕」「読み上げ」の2タブ構成。

- Electron の `main.js` が Python を探し、無ければ `winget` で導入 →`pip install -r requirements.txt`→`caption_server.py` を spawn する自動セットアップを持つ。ユーザーが Python 環境を自力で用意する必要はない
- ASR プロセス（Python）→ Node は `POST /api/caption/asr-text`（ループバック以外は 403）、Node → 表示は socket.io
- 表示経路は2系統。OBS ブラウザソース向けの `http://localhost:38201/overlay.html`（字幕）/ `http://localhost:38201/tts-overlay.html`（読み上げ）と、画面全体に重なる透過・クリック透過の Electron オーバーレイウィンドウ
- ポート 38200 が本体 API / socket.io、38201 は「本体が起動するまで待機ページを返し、起動後は 38200 へ 302 する」ローダー。OBS 側の URL を固定したまま起動順序を気にしなくてよくするための仕組み。同時起動は単一インスタンスロックで防いでいる
- 読み上げは `tiktok-live-connector` の `WebcastPushConnection` で TikTok Live に接続してコメントを取得し、**ローカルで別途起動している VOICEVOX エンジン（`http://localhost:50021`）**へ合成を投げる
- Stream Deck 等から叩く前提の制御 API（`/api/caption/*`、`/api/tts/*` の start / pause / resume / stop / pause-toggle / status）を公開している
- 設定は `%USERPROFILE%\.tikcaption-settings.json` の単一 JSON（`TIKCAPTION_SETTINGS_PATH` で差し替え可）。ファイルが一時的に読めないときは既定値で上書きせずスキップする

## Capabilities and Constraints

- **Windows 専用**。`winget` によるセットアップ、`taskkill /F /T` によるプロセス停止、NSIS インストーラなど Windows 前提の実装。macOS / Linux 対応の形跡はない
- **ASR は日本語モデル固定**（`nvidia/parakeet-tdt_ctc-0.6b-ja`）。他言語の音声認識は対象外。認識結果はビーム探索デコード（beam_size 10）を試み、失敗時は greedy にフォールバックする
- **初回起動時はネットワークが必要**。Python / 依存パッケージの導入と ASR モデルのダウンロードが走る。silero-VAD だけはインストーラに `extraResources` として同梱してあり、クリーンインストールでもオフラインでロードできる
- 発話区切りは VAD ベース（既定: 閾値 0.5 / 無音 800ms / 最短発話 500ms / 前パディング 200ms / 最大チャンク 4秒 / 継続時オーバーラップ 1秒）。長い発話は途中フラッシュされ、`isFinal=false` の暫定結果として扱う
- 字幕の補正は2段構え。**TikTok Live 向けの内蔵語彙表**（配信用語・ギフト名・バトル用語・配信者名など約200件、ひらがなルールはカタカナ変種へ自動展開）を先に当て、その後ユーザー定義の補正ルール（プレーン置換 / 正規表現）を当てる
- 表示側は文字数と句読点・文字種の切れ目でスコアリングして分割し、キュー滞留時は表示時間を 40%（最低1秒）へ短縮し、4件を超える滞留では中間セグメントを捨てて最新だけ残す
- 見た目は文字サイズ・縦位置・表示時間・1セグメント最大文字数・タイプライター速度・背景（透過/半透明）・フォント（Google Fonts の日本語フォント9種）・配色テーマ8種・縁取り幅まで設定できる
- **翻訳は非公式の Google 翻訳エンドポイント**（`translate.googleapis.com/translate_a/single?client=gtx`）に直接投げている。API キー不要で15言語（英・中・韓・仏・独・西・葡・伊・露・阿・泰・越・尼・蘭・土）へ訳せるが、公式サポートのない経路であり、レート制限・仕様変更・利用規約上の扱いは未整理
- **読み上げには VOICEVOX エンジンの別途起動が必要**。アプリは同梱していない。オーバーレイ側が2秒ごとに `/version` を叩き、連続2回失敗したらエラーを通知する。クレジット表記（`VOICEVOX:<ボイス名>`）を再生中に自動表示する
- 読み上げは音量・速度・ボイス選択・ランダムボイス（履歴付き、リセット可）に加え、**ブロック単語**（自傷・脅迫・差別・薬物系の既定リストを同梱、skip / 置換を選べる）、投稿者ごとのボイスマッピング、読み上げ変換、絵文字変換、エモート変換を持つ。合成は次の1件を先読みして再生の途切れを抑える
- TikTok Live への接続は自動再接続付き。オフライン時は30秒、その他は10秒後に再試行し、**90秒間まったくイベントが来なければ切断とみなして張り直す**（TikTok が無言で止まるケースへの対処）。署名は任意で **Eulerstream の API キー**を設定でき、レート制限エラーを検知して案内する
- ASR プロセスの自動再起動は最大3回まで
- 起動時の自動開始（字幕 / 読み上げそれぞれ）と、PC 起動時の自動起動に対応
- 自動更新は `electron-updater` の generic provider。ダウンロードは自動、インストールは終了時
- **収集・送信するデータはない**。音声も認識結果もローカルで処理され、外部へ出るのは翻訳リクエストと TikTok Live / Eulerstream / VOICEVOX への通信のみ

## Product Principles

- 配信中に触る道具として、設定より「開始 / 一時停止 / 停止」の3ボタンで完結させる。細かい調整は詳細設定モーダルへ退避させる
- 環境構築をユーザーに負わせない。Python も依存も VAD モデルもアプリ側が用意する
- クラウド ASR に依存せず、音声をローカルから出さない
- 配信が止まらないことを優先する。ASR も TikTok Live 接続も落ちたら黙って張り直し、字幕が詰まったら古いものを捨てて最新に追いつく
- TikTok Live という文脈に固有の語彙（ギフト名・バトル用語・配信者名）を製品側で持ち、ユーザーに毎回登録させない
- 他プロジェクトと連携しない独立プロダクトの立場を維持する

## Accessibility & Inclusion

字幕表示そのものが、音声を聞き取りづらい視聴者・音を出せない環境の視聴者への配慮として機能する。文字サイズ（16〜200px）、縁取り幅、配色テーマ8種、背景の透過/半透明切り替えにより、配信画面上での可読性を調整できる。翻訳表示は日本語を解さない視聴者に向けた導線。

読み上げのブロック単語には、自傷・脅迫・差別・薬物に関する既定リストを同梱しており、配信上で音声化されることによる二次被害を抑える方針を取っている。

アプリ本体の UI は日本語のみで、スクリーンリーダー対応・キーボード操作の個別要件は確認されていない。
