# Product

<!-- impeccable:product-schema 1 -->

## Platform

android, ios

## Users

主要ユーザーはLIVE Sidestage Analyticsに登録しているTikTok Live配信者。配信中、画面を注視せず手元操作を最小限に、自分のライブコメントを聞き取りたい人。Android/iOS同時展開を前提に、両OS向けのリリース作業を並行して進めている段階(公開実績・配布実績はまだ無い)。リリース後はLIVE Sidestage Analytics登録者向けの無料βを想定しており、そのためのエンタイトルメント・強制アップデート・アカウント削除・プライバシーポリシーは実装済み。

## Product Purpose

TikTok Liveのコメントとギフトをリアルタイムで取得し、コメントはVOICEVOX音声合成でスマートフォン上で読み上げ、受け取ったギフトに応じて効果音を鳴らす。配信者が画面を見なくても視聴者の反応を把握でき、配信中の実況やリアクションを止めずに応答できるようにすることが目的。

## Positioning

既存バックエンド「LIVE Sidestage Analytics」(Railway本番運用)の公式モバイルクライアント。「LIVE Sidestageへの登録＝LIVE Sidestage Analyticsの登録」という一体運用が前提。オンデバイスVOICEVOX(`voicevox_core`をdart:ffiで組み込み)による読み上げと、画面オフ/バックグラウンドでも途切れない常駐(AndroidはForeground Service、iOSは`UIBackgroundModes: audio`と無音キープアライブ)が中核の差別化ポイント。

## Operating Context

配信者はPC側の配信ソフト(OBS等)を操作しながら、本アプリをスマートフォンでバックグラウンド動作させる想定。サインイン(Google / Apple / メールアドレス+パスワードのいずれか)→初回のみTikTok ID連携(LIVE Sidestage Analyticsへの登録)→タブ画面で開始/停止を操作、という一直線のフロー。Socket.IOでLIVE Sidestage Analyticsバックエンドとリアルタイム接続し、`chat:comment` / `chat:gift` / `chat:follow` / `chat:battle` を受信する。**「開始」は読み上げと効果音で別々のボタン**になっており、TTSタブとサウンドタブがそれぞれ自分の開始/停止と配信状態を持つ。どちらも開始していない間はアプリを開いていてもsocketだけを張る「待機」状態で、音は鳴らさない。

## Capabilities and Constraints

- **Android/iOS両対応でリリース作業を並行して進めている。** 実機検証の蓄積はAndroid(Pixel 7a)が中心だが、iOS側もVOICEVOXのネイティブ統合・画面オフ中の読み上げ継続・Googleサインイン・Sign in with Apple・効果音ファイルの取り込みまで実装済みで、App Store審査向けの権限説明文とアプリアイコン・表示名も入っている。両OSとも配布(ストア公開)実績はまだ無い。
- VOICEVOXは6キャラクター(四国めたん・ずんだもん・春日部つむぎ・雨晴はう・玄野武宏・剣崎雌雄、計12スタイル)をオンデバイス同梱。投稿者ごとのランダムボイス割当(セッション限り、アプリ再起動でリセット)、またはランダムOFF時は設定タブで選んだ固定ボイス。選択肢は同梱vvmの静的な表(`lib/models/voice_catalog.dart`)から出す。
- 認証はGoogle Sign-In / Sign in with Apple / メールアドレス+パスワードの3系統。**GoogleとAppleは同じメールアドレスでも常に別ユーザー**として扱う。`AuthSession.provider`にどれでログインしたかを記録し、無言リフレッシュとログアウトの分岐、設定画面のアカウント表示に使う。
- 効果音は**ギフトのみ**。「ギフトを選ぶ → 音を選ぶ」の1行が設定の単位で、トリガー・イベント・カテゴリ・音源ライブラリといった中間概念は持たない。**音のみで動画は対象外**。
  - desktop(TikEffect)はトリガー種別・最低コイン数・対象ユーザー・複数音源の再生モードを持つが、本アプリでは意図的に落としている。設定を「ギフト名と音の対応表」に閉じるほうが、配信中に片手で触る道具として速いと判断した。
  - コメント・フォローでの発火は現時点で対象外。サーバー側の `chat:comment` / `chat:follow` 配信と受信経路は残してあるので、必要になれば設定を足すだけで戻せる。
  - まとめ投げ(コンボ)は1コンボにつき1回だけ鳴らす。連打回数だけ鳴らす選択肢は用意しない。
  - ギフト名は空欄にすると「すべてのギフト」に一致する。同じギフト名に複数の音を登録すると設定順に全部鳴り、1イベント10回で打ち切る。
  - 対応表は**最大5セット**まで持て、タブで切り替えて使う(`SoundConfig.maxSets`)。配信の種類ごとに音のまとまりを持ち替えるための単位で、セットの中はこれまでどおり「ギフト名と音の1行」の並び。停止中と開始中で編集できる範囲を切り分けている。
- ギフト名は `GET /api/mobile/gifts` が返す候補から選ぶ。候補は**TikTokの全ギフトカタログと、自分の部屋が最近受け取ったギフトの和集合**(2026-08-21時点の実測で666件。カタログはTikTok側の増減で変わる)。ピッカーは未入力なら全件を並べ、入力すると即時に絞り込む。コイン帯(1〜9 / 10〜49 / 50〜99 / 100〜199 / 200〜499 / 500〜999 / 1000〜4999 / 5000〜9999 / 10000以上)でも絞り込める。安い帯ほどギフトの種類が多いので、下ほど刻みを細かくしている。受け取ったことのあるギフトは先頭に寄せてチェック印を付ける。同じコイン帯をもう一度タップするとコイン数の昇順⇔降順が切り替わる。ギフト名に卑猥語を含む候補はブロックリストで一覧・検索から除外する(ひらがな・カタカナ問わず判定)。
  - カタログは analytics の Worker が30秒ごとの reconcile で `gift/list/` を叩き、2時間TTLで `tiktok_gift_catalog` に貯める。**まだ貰ったことのないギフトも事前に仕込める**。
  - **カタログも網羅ではない**(部屋限定ギフト、取得前の新ギフト)。そのため**一覧に無いギフト名はそのまま入力して登録できる**導線を残している。
  - **一致キーは英語のギフト名、表示と検索は日本語**。`GET /api/mobile/gifts` が返す `labelJa`(analytics が `gift/list/` を **`webcast_language=ja-JP`** で叩いて貯めたTikTok公式の日本語名。`app_language: "ja"` では返ってこない)を `lib/core/gift_name_ja.dart` が端末へキャッシュし、以後はオフラインでも引ける。更新は起動時とギフトピッカーを開いたときの2箇所。ピッカーは日本語名・英語名のどちらでも検索できる。日本語→英語の逆引きは意図的に持たず、保存する一致キーは常にTikTokが送ってくる名前のまま。
  - **一致キーに日本語を入れると無言で鳴らなくなる**が、配信者ごとのサブスクギフトはTikTok自身が日本語名で送ってくる(例:「わやハグ」)ため、日本語の一致キーが正しいケースが実在する。自由入力で日本語を禁止はせず、注意文だけ出す。
  - **同じ名前でコイン数の違うギフトが存在する**(`freestyle` は1コインと1800コインの両方)。一致キーは名前なのでどちらが飛んできても同じ音が鳴る。ピッカーは単一価格ではなく「1〜1800コイン」のように範囲で表示し、コイン帯の絞り込みも範囲の重なりで判定する。
  - 「受け取ったことがある」印はサーバーが直近5000行の履歴しか見ないため、厳密には「最近受け取った」の意味。
- 音源は3経路で取り込める: 端末内の音声ファイル選択、効果音ラボ検索、MyInstants検索。取り込んだファイルはアプリ専用ディレクトリに保存する(1ファイル5MB・合計200MB上限)。音源は1行につき1ファイルを専有し、行を消せば実ファイルも消える。効果音ラボ・MyInstantsの利用は両サイトの規約に抵触しており、公開前に別途対応が必要(同じ実装を持つdesktopと共通の課題)。
- 効果音の配信はbest-effort。サーバー側のコンボ状態が失われた場合は過少に鳴る(多重再生を避ける方を優先している)。
- **読み上げ・効果音の設定項目はすべて設定タブに集約する。** TTSタブとサウンドタブは配信中に見る運用画面で、状態表示と開始/停止だけを持つ。設定タブの内容はランダムボイス・固定ボイス選択・読み上げの音量・読み上げの速さ(50〜200%)・効果音の音量・TikTok ID変更・ログインアカウント表示・VOICEVOX利用規約・ログアウト・アカウント削除・プライバシーポリシー。音高とコメントフィルタは未実装。読み上げ速度は合成時にしか効かないので、変えても先読み済みの1件には反映されない。
  - どの設定も「開始しているか」では無効化しない。停止中の変更も永続化され、次の開始で背景Isolateが読む。止めるのは開始/停止の遷移中だけ。
- タブ構成は6つ(TTS / サウンド / 設定 / 貢献 / ギフト履歴 / バトル履歴)。後半3タブはanalyticsの集計をそのまま見る読み取り専用の画面で、日/週/月の切替に加えて**リスナー名検索と開始/終了日時のカスタム範囲による詳細フィルタ**を持つ(範囲上限366日。サーバー側 `range-limits.ts` の `MAX_RANGE_DAYS` と一致させる)。詳細フィルタ中でも日付の左右移動はできる。貢献/ギフト履歴はギフト受信で、バトル履歴は `chat:battle` で自動更新する。
- 開始してから60分ライブ配信が始まらなければ、読み上げ・効果音を自動的に停止する(復帰時にその旨を通知する)。
- 無料β向けのエンタイトルメント基盤を持つ。`GET /api/mobile/me` が返す `plan`(実プラン) / `mobileBetaActive` / `planLabel`(表示用ラベル、analytics正本の`getPlanDisplay`が組み立てる。β有効時は`βFREE`のように前置) / `features` / `minimumSupportedVersion` / `maintenanceMode` でUIを出し分け、最低バージョンを下回れば強制アップデート画面へ落とす。**これはUIの出し分け用の参照情報であって権限の最終防衛線ではなく**、実際の機能可否は毎回サーバー側が判定する。βは実プラン(`plan`)自体を書き換えるものではなく、機能ごとの制限を一時的にバイパスするだけ(プランバッジは`mobileBetaActive`のみを見る。analytics/eventsβはバッジに影響しない)。取得に失敗した場合は最も広く許可される側(FREE)へ倒し、`minimumSupportedVersion` だけは `0.0.0` にして取得失敗を強制アップデート扱いにしない。
- アプリ内からアカウント削除ができ、プライバシーポリシー(モバイル版はWeb版と分離)を開ける。ストア審査要件として持っている。
- 連打制御(rapid fire)、ユーザーIDのファイル一括指定、強制割り込み再生はdesktopにあるが本アプリでは未実装。
- バックエンドはLIVE Sidestage Analytics(Railway本番)。LIVE Sidestage単独のアカウント・データ基盤は持たない。

## Brand Commitments

アプリ名は「LIVE Sidestage」。PC・Webサービスと共通のブランド名であり、モバイル版の内部識別子は `live_sidestage_mobile`(Androidパッケージは `com.liveanalytics.live_sidestage_mobile`、iOSのBundle IDは**アンダースコアではなくハイフンの** `com.liveanalytics.live-sidestage-mobile`)とする。LIVE Sidestage Analyticsエコシステムの一部としての位置づけを維持し、独立ブランドとして切り離さない。

## Evidence on Hand

実機検証済み(Pixel 7a、Phase1〜3完了・2026-08-17)。

効果音機能とタブ構成(2026-08-21追加)も同じPixel 7a(Android 16 / API 36)で実機検証した。確認できたのは、3タブの描画と切替、MyInstants検索と音源の取り込み・保存・試聴、Foreground Serviceの起動とsocket接続、そして**TTSと効果音の同時再生**。同時再生は`dumpsys`とlogcatで裏づけを取っており、AudioTrackのセッションが別々に並走し、効果音側は`requestAudioFocus`を一度も発行していない(`AndroidAudioFocus.none`が効いている)。Foreground Serviceは実行時も`types=0x00000002`(mediaPlaybackのみ)で、`dataSync`は立っていない。効果音ラボとMyInstantsのHTMLパーサーは実際のレスポンスに対して別途検証した。

ギフト発火のエンドツーエンド(2026-08-21)は、ローカルanalytics(`dev:local` + `adb reverse`)へ実機を向け、内部API `/api/internal/gift-event` からギフトを注入して検証した。確認できたのは以下。

- 単発ギフトで音が1回鳴る(logcatの`AudioTrack: stop`のフレーム数で同定)
- コンボ3tick(repeatCount 1→3→5, repeatEnd)で**1回だけ**鳴る
- ギフト名が一致しないギフトでは鳴らない
- ギフトピッカーが`Rose`/`rose`/`  Rose  `を1件に畳み、新しい順に返す
- 全ギフトカタログを実際の`gift/list/`から取得できる(2026-08-21)。670件のレスポンスをgiftId重複4件で畳んで666件保存、ユニーク名638、同名で複数giftIdを持つものが27種類。既知の実受信ギフト名12件(Rose / TikTok / Finger Heart / Doughnut / Perfume / Corgi / Money Gun / Sports Car / Lion / Galaxy / Heart Me / GG)がすべて英語名でカタログと一致した。**この実測により、giftId照合ではなく名前照合を維持する判断を確定した**(同名の別giftIdを取りこぼすため)。24時間TTLによる再取得の抑止も同時に確認した

カタログ経由のギフト発火(2026-08-22)もPixel 7aで実機確認した。

- ピッカーが受信済みギフト(Lion / Sports Car / Money Gun / Corgi / Perfume / Doughnut / Finger Heart / TikTok)をチェック印付きで先頭に並べる
- **一度も受け取ったことのない`Zeus`(34000コイン)がカタログから候補に出て、選んで保存し、内部API注入で鳴った**(logcatの`AudioTrack: stop`で52416フレーム=Drumroll)。一致しないギフト名(`poseidon`)では鳴らない
- 同名で価格の違う`Freestyle`が1行に畳まれ「1〜1800コイン」と範囲表示され、コイン帯「1〜9」でも候補に残る(範囲の重なりで絞り込んでいる)
- 効果音側は`requestAudioFocus`を一度も発行していない(カタログ追加後も`AndroidAudioFocus.none`が効いている)
- 未保存の音源をテスト再生できる(設定を経由せずファイル名を渡すため)
- 行を削除すると設定反映を待ってから実ファイルも消える
- v1(トリガー構造)の設定からv2へ移行し、TTS設定と効果音の全体スイッチ・全体音量だけ引き継ぐ

貢献/ギフト履歴/バトル履歴の3タブ追加(2026-08-28)もPixel 7a(Android 16 / API 36)で実機検証した。ローカルanalytics(`dev:local` + `adb reverse`)にGoogleログイン(`GOOGLE_CLIENT_ID`を一時的にモバイル側`googleServerClientId`と同値へ設定して検証、確認後は空文字列へ戻し済み)→ TikTok ID `local_test_streamer` を連携し、事前にPrisma経由で投入した40件のギフトと1件のバトル(`scripts/seed-local-battle.ts`、相手tiktokId `local_test_rival`)を実データとして表示させた。確認できたのは以下。

- NavigationBarが6タブ(TTS/サウンド/設定/貢献/ギフト/バトル)構成でラベル折り返しなく描画される
- 貢献タブ: ランキング(順位・ニックネーム・ギフト数・コイン数)が降順で表示され、日/週/月の切替と日付範囲表示(週は「2026-08-24〜2026-08-30」形式)が正しく動く

- バトル履歴タブ: 相手tiktokId・終了ステータス・開始時刻・スコア(`1,200 - 900`)が表示され、タップで`showModalBottomSheet`から「このバトルの貢献者」が展開され、貢献タブと同じ行ウィジェットで表示される
- pull-to-refreshで一覧が再取得されエラーなく再描画される

検証中に、長時間起動し続けたアプリプロセスで`GoogleSignIn`の同一インスタンスがキャッシュ済みアカウントを再利用し、期限切れの`idToken`を送り続けて認証が失敗し続ける事象を確認した(サーバー側ログの`Token used too late`で特定)。アプリを完全に再起動して`GoogleSignIn`インスタンスを作り直すことで解消した。プロダクションでは「ログイン済みでない状態で1回だけ`signInWithGoogle()`を呼ぶ」という通常の使い方でしか発生しない経路のため、コード側の修正はスコープ外と判断した。

## Product Principles

- 配信中に画面を見ずに使えることを最優先する(音声中心、操作は最小限)。
- バックグラウンド・画面オフでも読み上げが途切れないことを機能の中核とする。
- LIVE Sidestage Analyticsとの一体運用を崩さない(アカウント・登録はLIVE Sidestage Analytics側に委ねる)。
- 個人開発者による実装優先の段階から、今後の一般公開に耐える品質へ引き上げる。

## Accessibility & Inclusion

現状、視覚アクセシビリティ(スクリーンリーダー等)の個別要件は確認されていない。日本語UIのみでi18n対応は範囲外。
